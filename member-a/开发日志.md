## 阶段二：建立分支与独立运行方案

**目标：** 遵守队长要求，先创建分支，再开发和提交。

**工作：** 在桌面仓库创建 feature/member-a-user-subsystem。保留商品、交易、共享文件及原 Maven 配置，新增 backend/user-pom.xml 和 UserStandaloneApplication，仅构建和扫描用户组件。

**问题：** 本机原有 Java 命令涉及多个 JDK；原项目编译目标为 Java 21。PATH 中没有 Maven，但发现 IDEA 自带 Maven。

**处理：** 用户独立构建采用可用的 JDK 17；保留团队 Java 21 目标。启动脚本检测 JDK 与 Maven，支持本机 IDEA 路径及 MAVEN_HOME。测试放在 src/test-user，避免给原构建引入未声明测试依赖。

**验证：** 用户独立后端可编译打包；原有配置文件保持不变。

## 阶段三：注册与数据存储

**目标：** 用户信息真实落库，避免明文保存密码及并发重复账号。

**工作：** 新增 UserDatabase、UserRepository 和 PasswordHasher。默认使用 H2 文件数据库，提供 PostgreSQL 环境变量接入方式；只初始化用户和 Token 两张表。账号统一小写，校验字符及长度，昵称去除空白。

**处理：** 密码使用 PBKDF2-HMAC-SHA256、600000 次迭代和随机盐；不使用普通摘要代替密码哈希。注册先检查账号，再由数据库唯一约束处理并发竞争。前端读取密码时不再使用会 trim 的公共 formValue，防止密码空格被悄悄改变。

**验证：** 检查库中保存的是密码哈希，公开响应无密码字段；大小写不同的同一账号按重复处理。50 个并发重复注册最终只创建一个用户。

## 阶段四：真实登录与请求身份

**目标：** 后端根据真实凭据识别当前用户。

**工作：** 完成登录密码校验、活跃用户检查、随机 Token 签发、Token 摘要存储、过期时间及 BearerCurrentUserContext；完成 UserFacade 的活跃用户查询。

**处理：** Token 明文只在登录成功响应中返回，数据库存 SHA-256 摘要。默认 8 小时过期。每次受保护请求检查 Token 是否存在、过期、撤销及用户状态。当前身份取自请求，不保存在单例可变字段中。

**并发考虑：** 登录签发 Token 前锁定用户行，确认密码哈希未被改动，防止旧密码验证与改密并发时仍签发凭据。

**验证：** 错误账号和错误密码使用相同提示；缺失、伪造、过期和停用凭据返回 401。50 个独立账号并发登录成功，随后各自只能读取本人身份。

## 阶段五：资料修改、退出与改密

**目标：** 完成用户功能闭环和会话失效规则。

**工作：** 实现当前资料查询、昵称/头像/电话修改、当前 Token 注销、旧密码验证、新密码更新与全部 Token 撤销。

**处理：** 不接受请求体中的用户 ID、账号或状态作为可修改字段。头像地址仅接受有主机名且不含凭据的 http/https URL。资料修改只作用于当前身份。重复退出已知 Token 返回 204。

**事务：** 改密与撤销全部会话在同一 JDBC 事务中完成，锁定用户后再次校验身份与密码版本；任何写入失败则整体回滚。

**验证：** 两个账号资料相互隔离，恶意附加字段不能更改他人身份；旧密码错误不影响现有登录；正确改密后所有旧 Token 失效。通过测试数据库约束主动制造撤销失败，确认密码与会话没有只更新一半。

## 阶段六：异常处理与频率限制

**目标：** 对非法输入、认证失败、重复注册和内部异常提供明确响应。

**工作：** 新增仅作用于用户 Controller 的异常处理；业务异常继承 ResponseStatusException，便于跨模块保留 HTTP 状态。成功和错误响应带 traceId，用户接口标记 Cache-Control: no-store。

**处理：** 注册按 IP 每分钟 60 次；登录按 IP 每分钟 120 次、按账号每分钟 60 次限流；返回 429 和 Retry-After。限流状态有数量上限并清理过期窗口，不信任客户端转发头作为 IP。

**验证：** 参数错误 400、身份错误 401、账号重复 409、限流 429、主动制造的内部存储故障 500 均符合约定；错误响应不暴露 SQL、密码或 Token。

## 阶段七：用户前端与独立联调

**工作：** 完善用户请求类型、错误信息、注册确认密码、改密确认密码、提交中状态和会话清理；移除用户登录对交易查询成功的依赖。新增独立 HTML、状态管理和 Vite 配置，复用用户页面。

**问题：** 原公共初始化先加载商品，商品 501 会阻止恢复用户；不能修改公共文件。

**处理：** 独立入口只请求用户接口，自行恢复身份，保留原共享初始化供团队负责人处理。原页面仍可复用用户组件。

**验证：** 浏览器实际完成注册、登录、保存昵称和刷新恢复。修改密码的成功、失败与会话撤销由 HTTP 集成测试验证；不将未执行的浏览器改密过程写成已验证结果。
