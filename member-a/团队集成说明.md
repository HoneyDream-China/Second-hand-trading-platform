# 成员 A 交付与团队集成说明

## 本次边界

成员 A 完成用户认证、资料和账号安全，不实现商品、交易、订单锁定或超时释放。所有既有非 user 文件都未修改。新建 user-pom.xml 提供独立构建，不影响团队原 pom.xml；测试放到 src/test-user，避免原项目没有测试依赖时被默认 testCompile 扫描。

独立后端只扫描用户包，独立前端只发用户请求，所以 B/C 服务仍是占位代码时也可以演示 A 的完整业务。

## 供 B/C 调用的接口

```java
CurrentUserContext.requireUser();             // 当前请求的真实活跃用户
UserFacade.getActiveUser(userId);             // 指定活跃用户的最小视图
UserFacade.existsActiveUser(userId);          // 是否为活跃用户
```

ActiveUser 只包含 id、nickname、status。B/C 不应读 users/auth_tokens 表、引用用户存储实体、接收客户端 userId 作为当前身份。商品归属和交易双方权限仍由 B/C 的 Service 检查。

用户业务异常 UserFailure 继承 ResponseStatusException，跨模块调用能保留 HTTP 错误状态。用户 Controller 的异常处理只作用于用户接口；如团队需要跨模块一致的 code/message/traceId，请由公共组件负责人把 code() 和状态接入公共异常处理，A 未修改公共处理器。

## 队长合并后需要协调的事项

1. **共享数据库驱动。** 原 backend/pom.xml 没有 JDBC 驱动，使用团队原启动方式前，需要公共配置负责人合并 user-pom.xml 中的 PostgreSQL 运行时依赖，并配置下述环境变量。用户代码本身使用标准 java.sql，不额外要求 JDBC 框架。
2. **共用数据源和事务。** 当前 A 的事务只覆盖 users/auth_tokens；B/C 的商品成交事务由其模块维护。后续共享数据源由团队统一，不能把两个不同的 JDBC Connection 误认为同一个事务。用户查询不参与商品成交原子写入。
3. **历史接口差异。** 本实现账号最少 3 字符、密码最多 128 字符、登录返回 expiresAt、资料 PUT 完整更新昵称和选填资料。历史 OpenAPI 的密码上限是 72，需由接口文档负责人同步。保留 UserView 的原字段，选填资料在响应中规范为字符串，兼容现有前端 User 类型。
4. **前端共享初始化。** 团队 shared/AppContext.tsx 仍先 await 商品接口，再恢复本人资料；商品失败会阻止恢复登录。A 未修改这个公共文件。独立入口已规避此问题，公共维护者合并时应让用户恢复独立于商品/交易加载。
5. **交易加载时机。** 用户页面已移除登录成功后等待 tradeApi.trades() 的耦合。C 应在交易页按需加载交易，或由公共维护者统一加载。退出和换号时 A 会清理共享交易状态，不改交易实现。

## 接 PostgreSQL

由数据库负责人执行原 db/V1__init.sql 或团队统一迁移。A 不会自动初始化 PostgreSQL 或改其他模块表。启动用户独立后端前设置：

```powershell
$env:USER_DB_URL='jdbc:postgresql://127.0.0.1:5432/campus_loop'
$env:USER_DB_USERNAME='campus_user'
$env:USER_DB_PASSWORD='由本机配置提供，不提交 Git'
```

实际操作时最后一行需替换为真实本机密码。支持使用环境配置 user.auth.token-hours 调整过期时间，范围 1–720 小时；独立演示默认 8 小时。敏感配置和真实用户数据不进入版本库。

本次已验证 H2 内存与文件模式，未在真实 PostgreSQL 上执行联调；正式整合还应验证 PostgreSQL 唯一约束、行锁和事务行为。
